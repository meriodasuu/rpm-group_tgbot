# Развёртывание

1. Создайте отдельную БД PostgreSQL для бота и read-only учётную запись RPM Club. Бот не должен владеть схемой RPM Club.
2. В `.env` заполните `TELEGRAM_BOT_TOKEN`, `BOT_DATABASE_URL`, `RPM_CLUB_DATABASE_URL`, `TIMEZONE`, `ADMIN_TELEGRAM_IDS`, `SUMMARY_CHAT_ID`. Не добавляйте `.env` в Git.
3. Выполните `docker compose up --build -d`; проверьте `docker compose logs -f bot`.
4. Настройте резервную копию БД бота (`pg_dump`) и регулярно проверяйте восстановление на отдельной БД.
5. Проведите сценарии из `ACCEPTANCE.md` на тестовых данных перед подключением рабочих сотрудников.

Сводка формируется ровно в 10:00 и 22:00 `TIMEZONE`. Каждая отправка получает уникальный ключ в `scheduled_jobs`, поэтому повторный запуск в ту же минуту не создаёт дубль. Ошибка доставки сохраняется как `failed` для контроля администратором.
