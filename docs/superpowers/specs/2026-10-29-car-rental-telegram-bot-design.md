# Telegram-бот учёта аренды автомобилей — дизайн v1

## Цель

Внутренний Telegram-бот даёт администраторам единый учёт клиентов, автомобилей, аренд и залогов: от одобренной СБ заявки до возврата автомобиля и отметки возврата залога. Он присылает сводки в 10:00 и 22:00 и показывает read-only данные RPM Club.

## Границы v1

- Доступ предоставляется только Telegram ID из allowlist; все допущенные пользователи — администраторы.
- Бот хранит учётные суммы аренды и залога и их статусы только для отчётности. Он не принимает платежи, не переводит и не возвращает деньги, не подключается к эквайрингу.
- Исключены автоматические сообщения клиентам, автоматический разбор переписки, изменение RPM Club и действие «+1».
- Связь с RPM Club — только чтение утверждённого `integration.v_members`; ключ — канонический UUID `user_id`. Доступные поля: `user_id`, `public_member_id`, `name`, `status`, `member_since`, `achieved_tier`, `total_rental_amount`, `created_at`. При нескольких результатах сопоставление подтверждает администратор.
- Если `SUMMARY_CHAT_ID` не задан, бот запускается, но плановые сводки не отправляет. После настройки отправляет их в 10:00 и 22:00 заданного часового пояса.

## Подходы

1. **Node.js/TypeScript + PostgreSQL + Docker** — выбранный вариант. Удобен для Telegram, планировщика, проверяемой доменной логики и запуска на сервере RPM Club.
2. Python/FastAPI + PostgreSQL — рабочая альтернатива, но не даёт преимуществ для пустого проекта.
3. Хранение в таблицах RPM Club — отвергнуто: нарушает изоляцию и правило отдельной схемы/БД бота.

## Архитектура

```text
Telegram -> Bot API (TypeScript) -> PostgreSQL bot DB
                                  -> integration.v_members (RPM Club, read-only)
                                  -> scheduler -> internal summary chat
```

- Сервис бота содержит обработчики Telegram и прикладной слой. Обработчики не реализуют правила статусов и конфликтов напрямую.
- Отдельная PostgreSQL БД (или изолированная схема) хранит данные бота, состояние форм, журнал событий и идемпотентные задания. Миграции не меняют RPM Club.
- Адаптер RPM Club использует отдельную строку подключения и таймаут. При ошибке источник помечается недоступным, а локальные операции доступны.
- Запуск — Docker Compose с переменными окружения. Секреты в репозиторий не попадают.

## Модель и процесс

- Клиент: имя, необязательные контактные данные, статус СБ (`не указан`, `одобрен`, `отклонён`), локальный статус (`новый`, затем `действующий` после первой завершённой аренды) и внешняя связь RPM Club.
- Автомобиль: внутренний код, марка/модель, идентификатор и доступность.
- Аренда: клиент, автомобиль, источник, период, фактическое завершение, учётная сумма, статус оплаты для отчёта и статус (`черновик`, `забронирована`, `активна`, `завершена`, `отменена`). Пересечения активных периодов одного автомобиля запрещены.
- Залог: сумма внесения/к возврату только как учётные данные, срок, статус и запись факта возврата. После завершения аренды создаётся задача на дату фактического возврата +14 календарных дней. Повторная отметка возврата блокируется.
- При завершении аренды фиксируются время, наличие повреждений и обязательный комментарий при повреждениях. Оценка клиента — обязательное целое от 0 до 5, вводится в форме завершения и отображается в карточке клиента.
- Изменения аренды, залога, статуса СБ и привязки RPM Club пишутся в audit log.

## Интерфейс

Команды `/start`, `/new`, `/find`, `/rentals`, `/deposits`, `/summary`, `/help`, `/cancel`, а также inline-кнопки. Многошаговые формы сохраняются в БД, подтверждают критические действия и переживают перезапуск. Пользовательский текст экранируется и всегда считается данными.

## Сводки и надёжность

Планировщик создаёт идемпотентные задания для 10:00 и 22:00. В сводке: активные аренды, выдачи сегодня, приёмки сегодня, залоги к возврату/просроченные. Пустой раздел — «Нет записей»; длинные сообщения разбиваются. Сбой отправки сохраняется и повторяется ограниченное число раз.

## Конфигурация

Обязательны: `TELEGRAM_BOT_TOKEN`, `BOT_DATABASE_URL`, `TIMEZONE`, список Telegram ID администраторов. Опциональны до выдачи: `RPM_CLUB_DATABASE_URL`, `SUMMARY_CHAT_ID`. Для RPM Club требуется отдельная read-only роль с `SELECT` только на `integration.v_members`; представление и роль создаются владельцем RPM Club.

## Проверка

Автотесты покрывают правила и приёмочные сценарии A1–A15, с тестовыми адаптерами Telegram и RPM Club. Отдельно проверяются идемпотентность повторного update/задания, сохранение формы и недоступность RPM Club.

## Оставленное для поставки

Администратор предоставляет токен бота, Telegram ID администраторов, часовой пояс и позже ID чата сводок. Владелец RPM Club создаёт представление/роль и выдаёт внутренний read-only доступ. Поля, отсутствующие в `integration.v_members`, не запрашиваются без отдельного согласования.
