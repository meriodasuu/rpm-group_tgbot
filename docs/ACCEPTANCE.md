# Приёмка v1

| ID | Проверка | Результат |
|---|---|---|
| A1 | Незарегистрированный Telegram ID | «Доступ запрещён», запись `access/denied` в аудите. |
| A2 | `/new` с валидными данными | Клиент, бронь, залог и аудит созданы. |
| A3 | Возврат раньше выдачи | Ошибка, форма не удаляется. |
| A4 | Пересекающаяся бронь | Сохранение блокируется. |
| A5 | Несколько совпадений при `/find` | Отображается список карточек, без автоматического объединения. |
| A6 | `/complete` первой активной аренды | Клиент `active`, залог `due` через 14 календарных дней. |
| A7 | `/complete ... yes` без комментария | Команда отвергнута. |
| A8 | `/extend` с конфликтом | Период не меняется. |
| A9 | Два `/deposit_return` | Вторая команда отвергнута. |
| A10 | 10:00/22:00 в заданной зоне | В чате одна сводка с 4 разделами. |
| A11 | Перезапуск во время `/new` | Следующее сообщение продолжает сохранённую форму. |
| A12 | Текст с «командой» в поле формы | Сохраняется как текст поля, не исполняется. |
| A13 | Доступный RPM Club | В карточке отображается сохранённый статус и время синхронизации. |
| A14 | Недоступный RPM Club | Локальные операции продолжаются; источник отмечается недоступным. |
| A15 | Несколько совпадений RPM Club | Связь не назначается без подтверждения сотрудником. |

Автоматически покрыты ключевые правила A3, A4, A6–A10, формирование сводки и поведение RPM Club при недоступности. A1, A2, A5, A11–A15 выполняются вручную в Telegram и на тестовом RPM Club перед запуском.
